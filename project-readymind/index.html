Problem

Making Hidden Body Signals Visible

In care-oriented conversations, a participant’s state is not always visible. Stress or tension may be present without clear outward signs.

Human review can read conversation and facial cues, but some stress signals may be hidden or difficult to judge visually. The design opportunity: how can multimodal body signals offer exploratory contextual cues about a participant’s state?

Multimodal Input

Three Signal Layers

Three physiological and perceptual signals are each processed independently, then merged into a single rule-based signal state for human review.

Galvanic Skin Response

GSR

Skin conductance / stress-related arousal cue. One signal among several — not a standalone emotional state measure.

BPM via Pulse Sensor

Heart Rate

Beats per minute / physiological activation cue. Contributes as one signal layer alongside the others.

Face Mesh Landmark Input

MediaPipe

Facial landmarks and head orientation as observable input — not an emotion-state measure.

Rule Logic

A Transparent Rule System

Each signal passes through threshold logic. The outputs merge into a rule-based score. The rule system is intentionally visible and interpretable.

One Concrete Example

Input

Heart rate reads 118 BPM during a session

→

Rule

The BPM threshold maps it to the high band (110–200)

→

State

The heart-rate component lowers the merged score

Every state maps back to a visible rule — nothing is inferred by a black box.

This is an exploratory prototype, not a clinical diagnosis system.

Signal States

Three Possible States

The interface presents a rule-based score (0–1) and one of three descriptive signal bands. This is exploratory signal representation — not an automated diagnosis.

High Band

0.74

0.68

Low Band

< 0.60

Ethical Boundary

The System Supports Judgment, Not Therapy

Human-in-the-loop

A human-in-the-loop concept: human review remains necessary. The interface is a cue, not a directive.

Supports Judgment

The prototype provides exploratory contextual cues to support — never replace — human judgment.

Not Diagnosis

The output is a rule-based signal state — not a diagnosis, and not validated clinical decision support.

Not Therapy

The system does not deliver therapy, diagnosis, or treatment.

What I Learned

  • —A cue must stay interpretable — every state change needs a visible rule behind it.
  • —Designing the boundary mattered as much as designing the signals.
  • —The project explores how rule-based signal states can be made visible and inspectable.
Current Limitations

What This Prototype Cannot Show

Limited prototype testing

Testing so far is limited to supervised prototype sessions.

Thresholds unvalidated

The threshold rules are illustrative and not clinically validated.

Signals are contextual

Physiological signals provide context, not a complete emotional picture.

No clinical validation

There is no evidence that the interface improves timing decisions, and no doctor has validated or adopted it.
